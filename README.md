# Linux C++ 线程池

基于 C++14 和标准线程库实现的 Linux 线程池。实现位于 `threadpool.h`，演示和复现用例位于 `main.cpp`。

## 功能

- 固定模式（`MODE_FIXED`）使用指定数量的工作线程。
- 缓存模式（`MODE_CACHED`）在队列满且提交等待超时后尝试扩容。超过初始数量的工作线程空闲约 60 秒后可退出。
- `submitTask()` 接收可调用对象和参数，通过 `std::packaged_task` 和 `std::future` 传递执行结果或异常。
- 可配置任务队列和缓存线程数量上限。默认队列容量为 4，提交等待队列空位最多 1 秒。

## 编译与运行

需要 Linux 和支持 C++14 的编译器。已在 GCC 8.5.0 上验证。

```bash
g++ -std=c++14 -pthread -DMY_DEBUG main.cpp -o /tmp/threadpool-repro
timeout 75s /tmp/threadpool-repro
```

`-DMY_DEBUG` 开启任务提交、扩容和工作线程退出日志。编辑 `main.cpp` 中对应的预处理开关，每次只启用下表中的一个场景。

| 场景 | 预期现象 |
| --- | --- |
| `REPRO_CACHED`（默认） | 队列满时触发扩容，触发扩容的提交仍抛出 `task queue is full`。约 60 秒后可观察到额外工作线程退出。 |
| `REPRO_SHUTDOWN` | 反复在任务运行期间销毁线程池。本次压力测试正常退出，析构顺序仍存在并发风险。 |
| `REPRO_BEFORE_START` | 启动前提交的任务保持等待，调用 `start()` 后返回 42。 |
| `DEMO_FIXED` | 两个工作线程处理求和任务。若队列饱和，被拒绝任务的 `future.get()` 会抛异常，演示中未捕获该异常。 |

## 已知问题与修复方向

- **关闭顺序**。在队列锁下更新关闭状态并唤醒等待者，排空已接收的任务。在析构函数体内释放队列锁后等待工作线程退出。
- **缓存线程回收**。当前空闲线程退出后，对应的对象仍留在 `threads_` 中。可标记已退出线程，由其他线程在队列锁外 `join()` 并回收。
- **队列满时的扩容和拒绝**。可在任务积压、无空闲线程且未达到线程上限时提前扩容，提交者继续在原等待期限内等待队列空位。
- **生命周期**。为启动前、关闭中提交任务以及重复调用 `start()` 定义明确的反馈。

## 计划扩展

增加带截止时间的提交接口 `submitUntil(deadline, fn, args...)`，将截止时间定义为任务最晚开始执行的时间。队列满时最多等到截止时间，已入队任务在出队时检查是否过期，并通过 `future` 区分等待超时和排队期间过期。用队列等待时间 P95、过期数和拒绝数展示突发负载下的行为。
